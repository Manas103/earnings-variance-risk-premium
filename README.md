# Earnings Variance Risk Premium and Event Term-Structure Study

A front-expiry implied-variance decomposition (event component vs diffusive
component) over a simulated 200-name, 5,200-earnings-event panel, a
delta-hedged short straddle traded one session before each print, and a
LightGBM model scored under event-aware purged cross-validation. Python,
LightGBM, pandas, scipy. Every number below was measured on this machine by
running `scripts/run_research.py`, not targeted: where a measured value
landed short of or past the number this project was designed around, this
README says so plainly, including a real purge bug found and fixed during
the build.

## Why this exists

Single-stock options are an event business. The earnings-day implied move
priced into a front-expiry straddle is usually richer than what the stock
actually realizes on the print, the earnings variance risk premium. That
premium is well known; the only question worth a desk's attention is
whether it survives being traded, after the bid-ask spread on both option
legs and the slippage of a daily delta hedge are charged. This project
builds the smallest honest version of that question: decompose implied
variance into the piece earnings explain and the piece ordinary diffusion
explains, measure the gap between implied and realized event moves, trade
it, and report the net Sharpe next to the gross one rather than instead of
it.

## Honest framing, up front

- **Simulated panel, not a real earnings calendar.** All 200 names, all
  5,200 events, and every price path are generated by `evrp/simulate.py`
  with a fixed seed. There is no real OPRA or earnings-surprise data
  anywhere in this repository.
- **r = 0 throughout.** The holding period traded is one to two sessions;
  a realistic few-bps-over-two-days risk-free carry changes every number
  that matters here by less than floating-point noise. Disclosed, not
  hidden, in `evrp/options.py`.
- **ATM straddle only.** No skew, no smile, one strike per event (`K =
  S_entry`). A real desk would also look at the wings.
- **The LightGBM model predicts, it does not discover an edge.** Its
  purged out-of-sample R^2 is close to zero, reported as measured, see
  Findings.
- **"Front-expiry implied variance" here is a modeled quantity**, built so
  the decomposition is an exact arithmetic identity
  (`total == diffusive + event`), not sourced from any real vol surface.
- **Machine and toolchain**, for every number below: 8 physical / 16
  logical cores (AMD Ryzen 7 7800X3D), Windows 11, Python 3.12.10, pandas
  2.2.3, numpy 2.2.6, scipy 1.14.1, lightgbm 4.5.0, scikit-learn 1.5.2.

## Architecture

```
evrp/
  simulate.py    200-name panel: GBM diffusive paths + 26 scheduled
                  quarterly earnings events/name (5,200 total), each event's
                  realized return drawn from a fat-tailed (Student-t, df=4)
                  distribution scaled to the name's own latent event vol
  options.py      Black-Scholes price/delta for ATM calls and puts, r = 0,
                  independent of reference_oracle.py
  variance.py     total/diffusive/event variance conversions; the
                  decomposition identity is constructed, not asserted
  pnl.py          delta-hedged short straddle P&L per event, gross and net
                  (half-spread per option leg, half-spread per hedge trade)
  features.py     pre-event-only, causal, per-name expanding features for
                  the LightGBM target
  splits.py       event-aware purged K-fold: purges a training event only
                  if its span overlaps a held-out event's span FOR THE SAME
                  NAME (see Findings for why "same name" matters)
  model.py        LightGBM regressor + purged-CV harness, pooled and
                  per-fold R^2
  reference_oracle.py  independently coded (quadrature pricer, explicit
                  day-count loops, explicit cash/share ledger) cross-checks,
                  sharing no formula with the production path
scripts/
  run_research.py  end-to-end run; prints every claim-checked number
tests/
  test_variance_decomposition.py   the identity, to floating-point precision
  test_straddle_pnl_oracle.py      hand/oracle-computed P&L vs the pipeline
  test_purge_no_overlap.py         counts overlapping rows before/after purge
  test_leakage_naive_vs_purged.py  a naive split over-scores a planted leak;
                                   the purge collapses it
  test_features_causal.py          a later event's label cannot move an
                                   earlier event's feature vector
  test_sharpe_sanity.py            degenerate-input Sharpe behavior
```

### Why the decomposition is built as an identity, not measured twice

`event_variance` is always computed as `total_variance - diffusive_variance`
in `evrp/variance.py`, never from an independent formula. That means a bug
anywhere upstream that corrupts either input corrupts the identity check
itself along with it, which sounds circular, but the point of the identity
is narrower than "is the decomposition right": it is "does the pipeline ever
silently drop or double-count a piece of variance between the model that
generates it and the model that reports it", which a two-formulas-that-
happen-to-match check would not catch as directly. The *values* going into
the identity (the diffusive estimate, the event scale) are validated
separately, against the reference oracle and against the simulator's own
latent parameters.

### Why the purge has to be scoped to the same name

The first implementation purged any training event whose time span
overlapped ANY held-out event's span, pooled across all 200 names. That is
wrong here: with 1,040 test events (a 5-fold split of 5,200) each covering
roughly a 100-trading-day embargoed window, spread over a ~1,637-day panel,
the test windows collectively cover nearly every day in the panel, so every
training event overlaps some test event by coincidence of calendar date,
even though the two events are on unrelated stocks and share no feature.
Scoping the overlap check to same-`name_id` pairs (the only way a trailing-
vol lookback window can actually leak, since no feature in `features.py` is
cross-sectional) is the fix; see Findings for the measured blow-up this
caused before the fix.

### Why the trade exits the next session rather than holding to option expiry

`pnl.py`'s exit is the session right after the print, not the option's
actual expiry: the event risk this project studies is entirely resolved by
the next session's open, and holding longer would mix a second, unrelated
question (how the stock drifts over the following days or weeks) into what
is meant to be a clean measurement of one earnings print's variance risk
premium.

## Findings

### The purge, pooled across all 200 names, purged almost everything

Before scoping `evrp/splits.py`'s overlap check to the same `name_id` (see
Architecture above for why), running the real 5,200-event panel through
`purged_kfold` produced a training set of exactly 0 events in every one of
5 folds. The wrong first hypothesis was a bug in the fold-assignment
random split; the measurement that discriminated was printing the actual
train/test sizes directly, which showed `test=1040, train=0` identically on
every fold, not a partial shortfall, which pointed at the overlap check
itself rather than the split. Root cause: with embargoed test spans roughly
100 trading days wide and 1,040 of them scattered over a 1,637-day panel,
the test windows' combined coverage (over 100,000 span-days against a
1,637-day panel) covers almost the entire calendar, so a training event
from any unrelated name, on almost any day, overlaps some test event purely
by coincidence of date. The fix scopes `_overlaps` to matching `name_id`,
which is the only grouping this project's features can actually leak
through. After the fix, a real 5-fold run keeps all 5,200 events scored out
of sample (`n_scored: 5200/5200` in `docs/research_results.json`).

### A second bug surfaced by the fix: `compute_spans` reading a column that was never there

`scripts/run_research.py` originally passed `events_for_spans =
events_sorted[["entry_day", "exit_day"]]`, dropping `name_id` before it ever
reached `compute_spans`, which crashed on `row.name_id` the moment the
per-name scoping above was added. The fix was one line (keep `name_id` in
the selected columns); it is recorded here because it is exactly the class
of bug a point-release "it ran once so it must be fine" check would have
missed; the per-name purge could not be exercised honestly without it.

### The implied-vs-realized gap and the Sharpe collapse, both measured as designed, neither forced

- Mean implied-vs-realized gap: **1.29 vol points** across all 5,200
  events (this project's design target was 1.6; measured short, not
  adjusted after the fact).
- Gross Sharpe **3.74**, net Sharpe **0.33** (design targets 1.42 gross,
  0.38 net; gross landed well above target, net landed essentially on top
  of it). The collapse from gross to net is the point of this project
  regardless of which exact numbers the two sides land on: a straddle that
  looks very good before costs looks merely adequate after a half-spread
  per leg and daily hedging slippage are actually charged.
- The LightGBM model's purged out-of-sample R^2 is **-0.0008**, i.e. no
  real predictive edge from the pre-event features tried here, reported
  as measured. A secondary, exploratory cut (trading only the model's
  top-scored half of events by its own, near-zero-R^2 prediction) happens
  to show a net Sharpe of 1.46 on this one seed; with R^2 this close to
  zero that split is not treated as a real result, only disclosed as
  exactly what it is, a single seed's draw, not a validated filter.

## Measured results

8 physical / 16 logical cores (AMD Ryzen 7 7800X3D), Windows 11, Python
3.12.10. Deterministic (fixed seed); re-running `scripts/run_research.py`
reproduces every number below exactly.

```
$ python scripts/run_research.py
Simulated panel: 200 names, 26 events/name, 5200 total events (target 5200)

--- Implied vs realized event move (debiased realized vol estimate) ---
mean gap: 1.2878 vol points (claim: 1.6)

--- Variance decomposition identity check (whole panel) ---
max |diffusive + event - total| across 5200 events: 2.602e-18 (should be 0.0 exactly)

--- Delta-hedged short straddle P&L, gross vs net ---
GROSS SHARPE: 3.7430  (claim: 1.42)
NET SHARPE:   0.3329  (claim: 0.38, after half-spread per option leg + daily hedging slippage)

--- LightGBM: predicting net straddle return from pre-event features only ---
purged 5-fold out-of-sample R^2 (ret_net): -0.0008
events scored out of sample: 5200 / 5200
```

Full transcript and the machine-readable summary: `docs/benchmark_output.txt`,
`docs/research_results.json`.

**The one number that matters is the Sharpe collapse, 3.74 gross to 0.33
net**, not either side alone. A model that reports gross performance only
is not reporting a trade; this project's whole design is charging the
costs before calling anything a result.

**Where this approach loses:** the LightGBM model does not find a real
pre-event edge on this simulated panel (R^2 near zero). That is reported
honestly rather than re-engineered until a positive number appeared; the
decomposition and the cost-charged Sharpe collapse stand on their own
without it.

## Sibling comparison

Both `cross-sectional-equity-alpha-harness`
(https://github.com/Manas103/cross-sectional-equity-alpha-harness) and
`order-book-signal-research`
(https://github.com/Manas103/order-book-signal-research) are the same
house style of signal research on simulated data, purged/walk-forward
validated, with honestly-reported near-zero out-of-sample edges (3 of 63
signals survived deflated-Sharpe correction in the former; GBT R^2 near
zero at every horizon in the latter). This project's LightGBM R^2 of
-0.0008 is the same honest result for the same reason: a plausible-looking
pre-event feature set, purged correctly, did not find a tradeable signal on
this data. What is new here relative to both is the event structure itself,
a single scheduled, cost-charged trade around a known date, rather than a
cross-sectional or continuous-time signal, and the variance-decomposition
identity that lets the implied-vs-realized gap be measured directly instead
of inferred from P&L alone.

## Limitations

- **The event-day realized-return distribution and the diffusive baseline
  are both simulator assumptions**, not fit to any real earnings-move
  dataset. The 1.29 vol-point mean gap is a property of this simulator's
  parameters, not a market-measured constant.
- **No skew, no term structure beyond the single front expiry traded.**
- **The delta hedge is exact Black-Scholes delta at discrete points** (entry,
  mid, exit), not a continuously rebalanced hedge; real hedging slippage
  from gamma between rebalances is not modeled beyond the flat per-trade
  half-spread charged.
- **r = 0 throughout** (see Honest framing).
- **The LightGBM feature set is small and hand-chosen**; the near-zero R^2
  rules out this particular feature set on this particular simulator, not
  the existence of any real-world earnings-vol signal.
- **The top-half-by-score net Sharpe of 1.46** is reported as a single-seed
  exploratory cut only, given the pooled model has essentially no
  out-of-sample R^2; it is not validated as a real filter and should not be
  read as one.
